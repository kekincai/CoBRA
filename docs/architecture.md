# 設計判断 / v0.1

- Python 3.12–3.13、FastAPI、NumPy、SQLite、Jinja2、自己配信 ECharts。単一組織・ローカル利用。
- 工数の内部単位は人月、通貨は円。規模単位はモデル内で厳密に一致。公開例の「千円」を保存。
- 原点通過 OLS: α = Σxy / Σx²。固定工数は回帰および CV 誤差指標から除外し、見積り時に加算。
- PCG64、Driver ID 昇順、同一 Seed、NumPy バージョン固定。案件順に依存しない。Driver は独立と仮定。
- 複数熟練者の Min/Mode/Max をそれぞれ等重みで平均。個別評価も履歴保存。混合分布との相違を明示。
- STD は案件別絶対相対誤差の母標準偏差（ddof=0）。分位点は linear 補間。
- 会社案件だけが本番校准に使用できる。公開例専用モデルを別識別子・画面状態で提供し、本番へ昇格しない。
- Driver/評価、モデル、見積り、工程配分・AI Scenario は追記のみ。モデルは案件と Driver のスナップショットを持つ。
- 見積りは全 trial とスナップショットを保存。閲覧では再計算しない。再計算は保存モデル・入力だけを使用。
- Review/Rework は AI 適用前工数 × A を既定の分母とし、工程 Baseline を分母にする設定も保存。
- 規模に依存しない Fixed Effort は AI 削減の対象外。工程ごとの追加 Fixed AI Effort は加算。
- 原価 = 人件費 + 管理費 + インフラ費 + AI運用費。提示価格 = (原価 + 予備費) / (1 - 目標粗利率)。粗利は提示価格 − 原価。
- ROI = (Baseline 原価 − AI 原価 − 追加投資) / 追加投資。投資ゼロは算出不可。投資の二重計上を避け、運用費と分離。
- AI 実績は別レコードで蓄積。AIモデルの作成は開発方式を明示して行い、従来モデルに混在しない。
- 規模・業種・技術・開発方式・開発種別の適用範囲警告。未知の事情の自動判定は対象外。
- 視覚方針: 紙に近い白、濃紺の文字、青の強調。情報密度のある研究用ワークスペース。
- 画面構成: 左ナビゲーション、作業領域、モデル・データの出所。数値・図表を中心に、説明は操作に必要な範囲。
- 操作方針: ページ切替の短いフェード、行の hover、計算中の状態表示。reduced-motion 対応。
